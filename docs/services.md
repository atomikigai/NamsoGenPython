# Contratos remotos observados

Este inventario describe las solicitudes y lecturas visibles en el cliente decompilado. La implementación Python y sus límites están en [remote-clients.md](remote-clients.md). Las lecturas reales realizadas constan en `evidence/services-live.json`; las demás operaciones sólo tienen demostración de transporte con fixtures. `k3.f` construye POST JSON para sus ramas de monedas/proxy y añade `X-Client-Key` con un valor embebido en el cliente en las ramas proxy y POST genérico (líneas 181-190, 247-260, 327-345); donde un campo de respuesta no se consulta, se marca así.

| Operación del cliente | Método / URL literal | Request observado | Response leído por el cliente |
|---|---|---|---|
| Acreditar monedas | `k3.e.a`, POST `https://api.spacehowen.com/users-coins/coins.php` (`k3/e.java:61-83`) | JSON `action=credit`, `id_token`, `purchaseToken`, `sku`, `quantity` | `ok`; si verdadero, lee `credited`, `already_credited`, `balance` y devuelve `balance`. |
| Consultar saldo | `k3.e.b`, POST misma URL (`k3/e.java:107-125`) | `action=get_balance`, `id_token` | `ok`, `balance`; devuelve balance solo con `ok=true`. |
| Gastar monedas | `k3.e.c`, POST misma URL (`k3/e.java:148-169`) | `action=spend`, `id_token`, `amount` | `ok`, `balance`; devuelve balance con `ok=true`. |
| Verificar suscripción | `k3.e.d`, POST `https://api.spacehowen.com/verify/verify.php` (`k3/e.java:195-212,223-244`) | JSON `token`, `sku`, `type=sub` | Lee `ok` como booleano; resultado se cachea en memoria hasta 45 s para ese token. |

`cards-checker` se usa aquí para endpoints de estado/cache; el fragmento también declara esa URL base (`h3/e1.java:116-127`). No se encontró en estos métodos un contrato del checker remoto que clasifique una tarjeta como viva o muerta: el cliente combina cache, estados locales y respuesta del lookup BIN. Por tanto, no se puede reconstruir el servicio de verificación a partir de estos contratos.
